Challenge

  • See reliability, latency, usage, errors and cost of inference in one place, per team
  • Alert before users notice; each alert leads to a runbook
  • Prove the alerts fire and resolve, not only that they exist

Solution

  • Prometheus scrapes vLLM, the GPU exporter, the gateway and the console (RAG evaluation scores)
  • 12-panel Grafana dashboard generated from code, one row per layer, plus a RAG agent row
  • 6 alert rules, each with a runbook link in its annotations

Trade-offs

  • Prometheus metrics only, no traces: cheap and enough for one model; a slow request cannot be followed across services
  • Alerts are visible on the dashboard and this page; no paging channel
  • Cost is computed from an assumed GPU price, not read from a bill

What I'd change at scale

  • OpenTelemetry traces: the gateway's otel callback into a collector, one trace per request from gateway to model
  • Alertmanager with routing per team and an on-call channel
  • Service level objectives with error budgets instead of fixed thresholds
