Solution incidents from this build

network

Every page came back as an empty 200

Symptom
Site reachable through the portal; every page returned status 200 with an empty body
Evidence
The origin's site address named one host, the portal sends the public name in Host (commit 34eb164)
Root cause
Caddy matched the site address against Host, so the public name matched no route
Fix
Site address without a host; bind keeps the listening address
Prevention
Pitfall 1 of the publishing page; its verify step requests the home page through the public name
cluster

Helm upgrade rejected the console's update strategy

Symptom
helm upgrade failed on the console Deployment
Evidence
Kubernetes rejected type Recreate together with defaulted rollingUpdate fields (commit 934f290)
Root cause
Helm 4 server-side apply merges with the live Deployment; its defaulted rollingUpdate fields make Recreate invalid
Fix
Strategy line removed; the console keeps a rolling update (on one node the ReadWriteOnce volume mounts in the old and the new pod alike)
Prevention
Runbook 05 starts every upgrade with helm history to find the last good revision
gateway

Per-team panels counted requests without a team key

Symptom
Per-team dashboard panels showed a series for requests that carry no team key
Evidence
Series with api_key_alias None or empty in the gateway request metrics (commit 1cef5b8)
Root cause
The gateway also counts requests without a team key; the panel queries grouped by alias only
Fix
Per-team panels filter api_key_alias!~"None|"; dashboard regenerated
Prevention
The status API team queries use the same filter; dashboard.json is generated by scripts/make_dashboard.py, so panels and code do not drift
site

README linked to a page the site did not build

Symptom
The public site answered 404 for the publishing page that README links to
Evidence
README linked to deploy/README.md; the builder rewrote the link to .html but built no such page (commit 53e8be1)
Root cause
The builder had no entry for deploy/README.md
Fix
Builder builds the page
Prevention
site/test_build.py and site/test_isc2.py check every local link of the built site
site

Console page made a request that always failed

Symptom
Every load of the console page sent a request that returned 404
Evidence
The browser asked for /favicon.ico on each load (commit 015d81f)
Root cause
No icon declared, so the browser asks for the default file
Fix
Inline data: icon in the page head
Prevention
Every isc-2 template declares the same inline icon
gateway

Gateway cache ignored the thinking mode of a request

Symptom
A request with thinking on got the cached answer of a thinking-off request in 0.02 s
Evidence
Same prompt again: 0.02 s and an identical body; a fresh prompt took 1.43 s, and with cache: no-cache the repeat took 1.51 s (check before the agent work)
Root cause
The exact-match cache key ignores chat_template_kwargs, so requests that differ only in thinking mode share one entry
Fix
Evaluation requests send cache: {"no-cache": true} (LiteLLM per-request cache control); the interactive ask keeps the cache
Prevention
Agent test of the no-cache flag, test_no_cache_flag_controls_the_cache_field (plan C.1.6)
