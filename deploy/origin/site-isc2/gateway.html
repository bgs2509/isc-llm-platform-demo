Challenge

  • Several teams share one model; one team must not starve the others
  • Every request is attributed to a team: tokens, spend, errors
  • Repeated questions should not cost GPU time twice

Solution follow one request

→ → → →

Team key

  • One virtual key per team, created by the bootstrap job from values.yaml
  • Unknown or revoked key → 401 before any model work

Limits and budget

  • Parallel requests and requests per minute per key
  • Spend budget per key; over budget → refused with a budget error

Cache

  • Same request → answer from cache, no GPU time, no model tokens
  • Exact-match cache; semantic cache in "What I'd change"

Model

  • One model alias qwen38 → the vLLM server
  • Streaming passes through unchanged

Accounting

  • Tokens and spend per key in Postgres; metrics per key alias in Prometheus
  • Cost per 1M tokens on the dashboard from GPU price per hour

Trade-offs

  • LiteLLM: keys, budgets and accounting out of the box; its overhead per request was not measured separately (every run goes through it)
  • Exact-match cache only: safe, but a reworded question misses it
  • Budgets in USD come from an assumed GPU price, not a bill

What I'd change at scale

  • Fallback to a second model and model pools per team: not possible here, no GPU memory for a second model on this host
  • Two gateway replicas with a shared Redis for limits and cache
  • Semantic cache measured on real traffic before it is turned on
  • SSO in front of key issuing instead of keys from configuration
